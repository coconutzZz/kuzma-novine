Naše novine 2026 - Gmail submission automation

INSTALL
1. Sign in to the Gmail account that receives the articles.
2. Open https://script.google.com/ and create a New project.
3. Replace the contents of Code.gs with the supplied Code.gs.
4. Open Project Settings (gear icon). Enable "Show appsscript.json manifest
   file in editor". Return to Editor and replace appsscript.json with the
   supplied appsscript.json. Save both files.
   The manifest enables the Gmail advanced service and requests read-only
   Gmail access. For a default Apps Script Cloud project, the Gmail API is
   enabled automatically. A custom/standard Cloud project needs the Gmail
   API enabled separately in Google Cloud Console.
5. Optional: adjust CONFIG at the top of Code.gs before the first setup.
6. Select setup in the function dropdown and click Run. Complete Google's
   authorization prompts using the mailbox that receives the submissions.
7. The execution log displays the main Drive folder and register links.
   A timer now checks incoming messages approximately every five minutes.
   The computer and browser do not need to stay open.
8. Send a test submission FROM ANOTHER EMAIL ACCOUNT, with the article title
   as its subject and a photo, PDF, or Word file attached. Wait for the next
   check, or run processSubmissions after at least 60 seconds. Verify its
   article folder and the Received row in the register.

DEFAULT BEHAVIOR
- The email subject becomes the article's folder name. Unicode letters,
  including š, č, ć and ž, are preserved. Slashes/control characters are
  replaced with spaces and very long folder names are shortened.
- Every incoming email containing supported attachments is one submission.
  Multiple attachments in an email share one folder and one register row.
  Separate emails with the same subject get separate folders; the later
  folder has a Gmail message ID suffix. Replies are separate submissions.
- The root folder is named Naše novine 2026. setup reuses one existing
  root-level folder with that exact name, or creates it if absent. Set
  MAIN_FOLDER_ID to use a specific existing My Drive folder elsewhere.
- The register is a separate Google Sheets file named
  Naše novine 2026 - Evidencija. It contains these visible columns:
  Email subject | Sender | Received date | Drive folder link | Status
  Status starts as Received. You can edit the status later.
- A hidden sixth column stores Gmail message IDs to prevent duplicate rows.
  Keep this column and existing rows. Do not rename/reorder the headers.
- The received date is Gmail's internal delivery timestamp, displayed in
  the script's timezone (Europe/Vienna in the supplied manifest).
- The original message, its attachments, and its read/unread status remain
  in Gmail. This script only requests read-only access to Gmail.
- Photos/images, .doc, .docx, .docm and PDF files are copied as original files.
  Files with generic MIME types are also recognized by their extensions.
  Other attachments are ignored; ZIP files are not unpacked. Messages with
  no supported attachment do not create a folder or a register row.
- Embedded image attachments are included by default, which can include
  signature logos. Set INCLUDE_INLINE_IMAGES to false to omit those.
  Images hosted on external websites are not downloaded. An email with
  only inline images may not match Gmail's has:attachment search.
- Sent mail, drafts, spam and trash are excluded. Archived incoming mail
  is included. No unread filter is used, so reading an email does not
  prevent processing. Self-sent messages carrying the SENT label are skipped.
- New mail is processed from installation onward. To include older mail,
  set START_FROM before the first setup, e.g. 2026-01-01T00:00:00+01:00.
- EXTRA_GMAIL_QUERY can restrict intake to the editorial address or label,
  for example to:redakcija@example.com or label:Articles. If you add/change
  a matching label after a message is older than the one-day overlap window,
  it will not be picked up by the normal incremental scan.
- Leave MAIN_FOLDER_ID and SPREADSHEET_ID empty for automatic creation.
  To use existing resources, set their IDs before setup. A Drive folder ID
  is the text after /folders/ in its URL. A spreadsheet ID is the text
  between /d/ and /edit in its URL. Use a My Drive destination for this
  version; shared-drive deployments need the advanced Drive API.
- Setup can be rerun without creating another timer or resetting the start
  date. Configuration of resources and START_FROM is intended for initial
  installation; changing those later does not automatically migrate data.
- Partially completed saves are retried, using existing article folders and
  numbered filenames. A Received row is written only after all supported
  attachments have been saved. Avoid editing pending folders/filenames.
- Gmail search is rechecked over a one-day overlap to accommodate delayed
  indexing. Exceptionally longer indexing delays can require a manual backfill.
- The script is intended for normal editorial submission volumes. Google's
  Apps Script/Gmail/Drive quotas and available Drive storage still apply.

STOP / TROUBLESHOOT
- Run stopAutomation to remove this script's checking timer.
  Run setup again to resume. No emails, files or rows are deleted.
- In Apps Script, open Executions to inspect failures. Failed submissions
  are retried automatically; fix permissions, quota/storage or deleted
  destination resources if retries keep failing. Other messages in the
  same run can still be registered successfully.
- If you see "Gmail is not defined", check that the supplied manifest was
  saved. Alternatively add Gmail API under Editor > Services > +.
- The same Google account should install and run the automation. The timer
  runs as its creator, and uses that person's Gmail, Drive, and permissions.
- Review/test this script in your own Google account before relying on it.
  Local verification uses simulated services, not your live mailbox.
